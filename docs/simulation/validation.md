# 検証計画

## 数式と既知境界

- `b = 0`、`a = 0`で第一安定領域の上端`q`が約0.908となることを確認する。
- 無抵抗の境界をMathieu特性値または高精度参照計算と比較する。
- 各計算点で`det(M)`と`exp(-b pi)`の差を記録する。
- `q = 0`など係数が定数になる場合を解析解と比較する。
- 軸方向と半径方向のパラメータ変換を独立にテストする。

## 独立実装との比較

Pythonの高精度参照計算とC++本番計算を、小さい固定パラメータ集合で比較する。比較対象はモノドロミー行列、Floquet乗数、安定分類、境界位置とする。

## 収束試験

- 1周期あたりの積分step数を倍増し、境界移動量を測る。
- 適応積分を参照に使う場合は相対・絶対許容誤差を変える。
- 格子幅を変え、境界補間による誤差を測る。
- 捕獲判定では観測時間を増やし、分類が変わる点を記録する。

許容誤差は結果を見て後付けせず、用途ごとに事前定義する。

## 軌道と単位

- 物理時間と無次元時間の相互変換を往復テストする。
- 物理速度と無次元速度の変換をテストする。
- `x`、`y`、`z`から幾何学的半径を計算し、電極衝突判定を確認する。
- 重力を0にした対称性と、電圧を0にした極限を確認する。

## 性能評価

同一条件で次を測定する。

- 1点、1万点、100万点の実行時間
- スレッド数に対する速度向上
- 1点あたりの出力量と全体の保存容量
- Python参照実装、C++単一thread、C++ OpenMPの比較

性能最適化は、数値的一致と収束が確認された後に行う。

## 回帰テスト用基準値

最初の実装PRで、入力、期待値、許容誤差、生成方法を明記した小さな基準データを追加する。大きな結果ファイルや画像のpixel単位比較には依存しない。

## 実施記録

### 2026-10-06: Phase 1・Phase 2

対象: `scripts/floquet_reference.py`（scipy `solve_ivp` DOP853、`rtol = 1e-12`、`atol = 1e-14`）と`src/floquet*.cpp`（固定刻みRK4、1周期2000 step）。分類許容値は`eps = 1e-8`（暫定）。

数式と既知境界:

- `q = 0`で行列指数関数の厳密解と`1e-10`以内で一致（Python、C++）。
- `b = 0`、`a = 0`の第一安定領域上端は二分法で`q = 0.908046`（基準値との差`2e-6`以内）。
- 減衰系と無減衰Mathieu方程式の変換関係`lambda = exp(-b pi/2) mu`（`a -> a - b^2/4`）をPythonで確認。
- `det(M) = exp(-b pi)`: 大きい`b`では`exp(-b pi)`が行列要素より桁違いに小さく、`m00 m11 - m01 m10`の桁落ちが誤差を支配する。このため単体テストでは誤差を`abs(m00 m11) + abs(m01 m10)`で規格化して`1e-9`未満を要求する。走査出力の`det_error`は絶対誤差のまま記録する。

独立実装との比較:

- `b = 0, 0.5, 6`の9×9格子（`q_z`最大20）で、C++とPythonの分類が全点一致し、モノドロミー行列が`1e-9 * max(1, max|M|)`以内で一致。
- C++の出力はスレッド数1と8でビット単位一致。

収束:

- `rho = max|lambda|`は2000 stepで`q <= 17`程度まで相対`1e-11`程度に収束。`q = 30`、`b = 10`でも相対`1e-10`程度。
- 401×401格子（`b = 0`: `a_z in [-0.4, 0.2]`、`q_z in [0, 1.2]`、`b = 6`: `a_z in [-3, 3]`、`q_z in [0, 20]`）で、500〜4000 stepの分類は8000 stepと全点一致。これは境界移動が格子間隔未満であることだけを示し、境界位置の精密な収束はPhase 3で評価する。

性能（KEKCCログインノード、g++ 11.5、CMake Release（`-O3`）、2000 step、共有負荷下の参考値）:

| 条件 | 時間 |
| --- | --- |
| C++ 1点、1 thread | 6e-5 s |
| C++ 1万点、1 thread | 0.58 s |
| C++ 約10万点、1/2/4/8 threads | 5.7 / 2.8 / 1.4 / 0.72 s |
| C++ 100万点、8 threads | 7.1 s |
| Python参照、1点あたり | 約4e-3 s |

### 2026-10-06: Phase 3（境界追跡）

対象: `src/floquet_boundary.cpp`（RK4 2000 step、二分法許容幅`1e-9`）。目標精度は境界位置の絶対誤差`1e-6`。

- `b = 0`の境界点（`a_z in [-1.5, 1.5]`、`q_z in [0, 4]`）は、律速方向のMathieu特性値曲線`a_n(|q|)`、`b_n(|q|)`（`scipy.special`、独立な参照）から最大`4e-10`（`a_z`単位）。
- `b = 2, 6`の境界点で、精製した格子辺に沿って`±1e-6`動かすとPython参照計算の安定余裕の符号が反転する。
- step数収束（16000 stepを基準、`q_z > 0.5`、`b = 0, 4, 8`）: 1000 stepで最大`3e-7`、2000 stepで`2e-8`、4000 step以上で`1e-9`。原点近傍では`1e-7`〜`1e-6`程度で頭打ちとなる（`stability.md`の既知の制約）。
- スレッド数1と8で出力CSVが一致。
- 粗格子依存: 既定窓で`b = 0, 1, 2, 3`の安定領域数は、241²で`2, 2, 4, 3`、481²で`3, 4, 3, 3`、961²で`3, 3, 3, 3`。細い島の検出は格子に依存し、既定の241²では不十分な場合がある。
- 計算量: 既定設定（241²、11断面）で約6秒（8 threads）。481²で約22秒、961²で1断面約7秒。

### 2026-10-06: Phase 4（3次元軌道、Python参照）

対象: `scripts/trajectory.py`、`tests/test_trajectory.py`。

- 電圧0: Stokes抵抗つき自由落下の解析解と位置`1e-11 m`、速度`1e-8 m/s`以内で一致。
- 重力0: 初期条件の符号反転に対して軌道が点対称。
- 時間・速度の往復変換、March規約の`a_z`、`q_z`をテスト。
- 重力0・電極なしで、RF周期ごとのストロボ振幅の増減率が各方向の`log(max|lambda|)`と相対`1e-3`以内（実測では5桁）で一致。軌道積分とFloquet計算の独立な照合になっている。
- 電極衝突: 衝突点が電極面の式を`1e-9`以内で満たす（エンドキャップ、リング）。
- 例の設定（`b ≈ 4.94`、`q_z ≈ 2.95`）では、減衰が強いため軸方向は数RF周期で静止し、半径方向は1周期あたり約10%ずつゆっくり減衰する。重力による平衡位置のずれは約35 um。

### 2026-10-06: Phase 5a（C++軌道エンジン）

対象: `src/trajectory.cpp`、`src/trajectory_run.cpp`、`tests/test_trajectory_cpp.py`。

- Python参照（DOP853、`rtol = 1e-10`）との比較: RF 1周期800 stepで、捕獲・脱出、衝突電極、位置（`1e-7 r0`以内）、速度、脱出時刻（相対`1e-8`以内）が一致。捕獲2例、RF位相あり、DCあり、エンドキャップ・リング衝突、RFなしの落下を含む。
- 既定の200 stepでの精度: 脱出時刻の相対誤差は約`3e-7`（15 m/sの高速粒子）、4次収束を確認。位置の誤差は捕獲軌道で約`2e-9 r0`。
- 衝突点は電極面の式を`1e-9`以内で満たす。
- 性能: 200 step/RFで1 stepあたり約0.3 us、RF 1周期あたり約60 us（1 thread）。観測時間RF 200周期の捕獲軌道1本で約12 ms。
